# YMR Global — Link Hub

A static React site for YMR Global group links, custom forms, and QR codes.

## Admin

- Open `/admin` to manage the main landing page and a separate department landing page at `/departments`.
- Create forms with short answer, email, phone, long answer, and dropdown fields.
- Each form gets a short shareable `/f/<slug>` URL. Existing `/form/<slug>` URLs continue to work. Use the form's URL slug field to choose a concise name such as `reg-team`.
- Open a form's response viewer to review submissions, see submission and active-day totals, and export a CSV.
- Paste any URL into the QR code maker and download its QR image.

## Supabase setup

The SQL schema is in `supabase/schema.sql`. It creates the links, forms, responses, QR codes, click/scan event tables, row-level security policies, and public tracking RPCs. The React app uses Supabase for admin sign-in, shared data, public form submissions, and tracked redirects.

1. Create a Supabase project in the [Supabase Dashboard](https://supabase.com/dashboard).
2. Open **SQL Editor**, create a query, paste all of `supabase/schema.sql`, and run it once. If the project already has the earlier schema, run `supabase/forms_upgrade.sql` instead; it adds the department landing-page column, custom form settings, and upload buckets without replacing existing data.
3. In **Authentication > Users**, create your admin user. Disable public sign-ups after creating the admin account.
4. In SQL Editor, grant the admin user access by inserting their user ID:

   ```sql
   insert into public.admin_users (user_id)
   select id from auth.users where email = 'YOUR_ADMIN_EMAIL'
   on conflict (user_id) do nothing;
   ```

5. Copy the **Project URL** and **Publishable key** from **Project Settings > API Keys** (or the **Connect** panel). Put them in a local `.env` file using `.env.example` as the template. The publishable key is designed for browser use; never put a `secret` or `service_role` key in a `VITE_` variable or commit one to Git.
6. Add those same two public values as environment variables in your hosting provider, then redeploy. For local development, create `.env.local` with those values and restart Vite.
7. To load the original WhatsApp groups, run `supabase/seed.sql` in SQL Editor. It is safe to rerun.

Use `npm run dev` to run locally after setting `.env`. See Supabase's [React quickstart](https://supabase.com/docs/guides/getting-started/quickstarts/reactjs) and [API key guidance](https://supabase.com/docs/guides/getting-started/api-keys).

The schema does not expose response records, QR management, or click/scan event rows to anonymous visitors. Forms permit public submissions; tracking functions return the destination URL while recording an event. The publishable key is safe in browser code because row-level security enforces these access rules.

Form header images and response attachments are limited to 5 MB in Supabase Storage. Header images are public so they display on shared forms. Response attachments are private and can be opened from the admin response viewer.

The QR image is generated by `api.qrserver.com`, which receives the URL or text being encoded.

## Local development

```sh
npm install
npm run dev
```

## Build and deploy

```sh
npm run build
```

The output is in `dist/`. Vercel rewrites are included for direct navigation to `/admin`, `/departments`, `/f/...`, and legacy `/form/...` routes. Other static hosts need an equivalent SPA fallback that serves `index.html` for these paths.
